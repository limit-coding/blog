我设想碳数据监测系统时，最初很容易被“让智能体自动浏览、自动理解一切”吸引。继续拆解后我发现，这类系统最重要的不是自动化程度，而是每个数字能否解释来源、计算规则和不确定性。

## 先建立数据谱系

原始数据可能来自公开接口、经过授权的页面、人工表单、设备读数或文件导入。每条记录除了数值，还应保存：

- 来源与许可范围；
- 采集时间、时间粒度和单位；
- 原始快照的校验值；
- 解析器与计算规则版本；
- 缺失、估算和修订标记。

这样结果发生变化时，才能回答“是现实变了，还是算法变了”。

## 确定性任务交给确定性程序

定时抓取、单位换算、字段映射、重复数据消除和公式计算，都应该尽量使用可测试的普通程序。它们输出稳定、成本可控，也便于审计。

大模型更适合处理结构不固定的环节，例如从格式各异的公开报告中定位指标候选、解释异常文本或辅助生成字段映射。但模型输出不应直接成为最终事实，而要经过 schema 校验、规则复核，关键数据还需要人工确认。

```text
授权来源 → 原始层 → 标准化层 → 指标层 → 展示与告警
                 ↘ 失败样本与人工复核 ↗
```

## 把异常分成三类

数值突然变化，可能是现实事件、采集故障，也可能是口径变化。告警系统应同时比较历史区间、相邻来源和元数据，而不是只设一个固定阈值。

我会把告警说明写成“观察到什么、可能原因、还缺什么证据”，避免让自动生成的解释伪装成已确认结论。

## 合规本身也是架构

采集程序需要遵守数据许可、访问频率、站点规则和隐私边界。系统应支持删除来源、撤回数据和重新计算下游指标。若一个数据源必须依靠绕过访问限制才能获得，它就不应成为生产管线的基础。

AI 可以降低非结构化数据的整理成本，却不能替代来源管理和责任判断。对碳数据这样的公共议题而言，可追溯、可复算和诚实表达不确定性，比一张看似聪明的自动化架构图更重要。
