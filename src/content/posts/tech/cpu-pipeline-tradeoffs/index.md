# cs61c


ALU的数量

你手搓的 CPU 只有一个 ALU，这太正常了，因为这正是最经典的单发射（Single-issue）架构。
在 CPU 设计里，ALU 的数量和“**发射宽度（Issue Width）**”是直接绑定的。一个 CPU 每个时钟周期能同时发射（执行）多少条指令，就需要有对等数量的执行单元（Execution Units）去消化它们。
如果把 CPU 内部的译码器（Decode）比作**点单的前台**，那 ALU 就是**后厨的厨师**。前台一次点几个菜，后厨就得配几个厨师，不然菜就会在传送带上堵死。
我们来一个一个盘盘这几家“神仙芯片”的后厨到底塞了多少个 ALU。
## **1. 你手搓的 CPU：单发独苗**
* **ALU 数量：1 个****后厨情况**：前台（Decode）一个周期只能翻译 1 条指令（比如 addi）。后厨就你这一个全能型 ALU 顶着，算加减法是你，算逻辑运算（AND/OR）是你，连 beq 算分支跳转地址或者 sw 算内存偏移量，也都得借用你这个唯一的 ALU。
## **2. STM32 (Cortex-M4/M7)：实时精益流**
* **ALU 数量：1 到 2 个****后厨情况**：
	* 像 **STM32F4 (M4)** 这种，由于是严格的**单发射**，它内部也只有 **1 个主整数 ALU**（带硬件乘除法器）。
	* 而到了高端的 **STM32H7 (M7)**，它支持**双发射（Dual-issue）**，前台一周期能点两个菜了。所以苹果和 Arm 工程师给它配了 **2 个 32位 整数 ALU**。这样如果代码里连续出现两条没有依赖关系的 add，它们就能并排同时在 1 个周期内算完。
## **3. 树莓派 5 (Cortex-A76)：乱序四人组**
* **ALU 数量：3个 整数 ALU + 1个 整数分支单元****后厨情况**：Cortex-A76 是 **4 发射**。这意味着前台一秒钟送进来 4 条微操作。为了接住这些指令，它的乱序执行核心里布置了：
	* **2 个基础 ALU**（负责简单的加减法、逻辑运算，1 周期就能出结果）。
	* **1 个复杂 ALU**（专门负责硬件乘除法、数据类型转换等吃力活）。
	* **1 个单独的分支处理单元（Branch Unit）**：专门用来处理跳转、分支指令。在硬件上，它其实也是个特化的 ALU，只负责算 PC 偏移量。
## **4. Intel i9 13代 (Raptor Cove 大核)：老牌肌肉流**
* **ALU 数量：5个 整数 ALU + 2个 分支单元**（仅算整数部分）
* **后厨情况**：Intel 的 P-Core 是 **6 发射** 乱序架构。后厨的规模开始变得极为夸张：
	* 它拥有 **5 个独立的整数 ALU 端口**（Port 0, Port 1, Port 5, Port 6, Port 10 后面都挂着 ALU）。
	* 不仅如此，它还有 **2 个专门的分支计算单元**，以及 **4 个负责算内存地址的 AGU**（Address Generation Unit，这也是一种特殊的减法/加法 ALU，专门用来给 Load/Store 指令算内存物理地址）。
	* 这意味着，如果你的代码里全是纯整数运算，i9 在极端工况下一个周期可以同时轰出 5 条算术结果。
## **5. 苹果 M2 / M4 / M5 (大核)：丧心病狂的屠宰场**
* **ALU 数量：6个 到 8个 整数 ALU + 2个 分支单元****后厨情况**：还记得前面说苹果是 **8到10发射** 的高 IPC 狂魔吗？既然前台敢一次性放 8-10 条指令进来，后厨就必须密密麻麻地排满人。
	* 以 M2 大核为例，它直接拍了 **6 个满血的整数 ALU**。
	* 外加 **2 个独立的分支计算单元（BRU）**。
	* 再加上 **3 个存取地址通用型 AGU**。
	* 光是打杂的整数和地址计算单元，苹果大核里就并排躺着 **11 个小 ALU**。更不用提它旁边还挂着一整排恐怖的 128位/512位 矢量/神经网络执行矩阵（AMX/NEON）。
**🧠 总结：为什么不无限增加 ALU 数量？**
你可能会想：“既然苹果堆 6 个 ALU 这么猛，Intel 为什么不堆 20 个？”
这里有一个硬件设计上的**边际效应递减定理（Amdahl's Law 的硬件变体）**：
1. **数据依赖卡脖子（Data Hazard）**：写代码时，下一行常常要用这一行的结果。比如：
3. add x1, x2, x3   # 必须先算出 x1
4. sub x4, x1, x5   # 才能算这一步
5. 这两条指令无论如何都必须串行，你后厨有 100 个 ALU，第 2 条指令也得老老实实排队等第 1 个 ALU 算完。
6. **寄存器堆冲突（Register File Ports）**：1 个普通 ALU 需要 2 个读端口和 1 个写端口。如果要同时跑 6 个 ALU，你的寄存器堆就必须支持在一个周期内同时被读取 12 次、写入 6 次！这会导致寄存器堆的电路面积呈平方级（$O(N^2)$）暴涨，发热量和延迟会直接把芯片烧毁。
所以，你手搓的小 CPU 拥有 1 个 ALU，是最具性价比、最能体现控制逻辑、也是物理上最优雅的结构。现代工业界折腾了几十年，把寄存器堆重构成了复杂的“重命名寄存器和保留站”，才艰难地把 ALU 数量从 1 个推到了 6 个。
你目前在 Logisim 里，这个唯一的 ALU 是把加法器、移位器用一个大 MUX（多路选择器）拼起来的吗？还是已经开始头疼怎么给它加硬连线的乘法器了？

关于流水线数量的设计，只有这个小例子是5级流水线


如果你去扒苹果 **M2、M4 甚至到刚推出的 M5 芯片** 的底层微架构（Microarchitecture），你会发现它们在现代 CPU 工业界里是一类**极其独特的怪物**。
它们不仅和 Intel 的 i9 流派截然不同，而且把你在 CS61C 里学到的所有“宽度”概念拉到了当今世界的物理极限。
## **1. 它们的流水线深度：比你想象的要浅（14 ~ 16 级）**
很多人以为苹果 M 系列芯片单核性能这么猛，流水线一定深得飞起。但实际上，根据目前顶级硬件评测机构（如 AnandTech 和各路逆向工程大佬）的测算：
* **M2 / M3 / M4 / M5 的大核（Performance Core）**：基本整数流水线深度仅在 **14 到 16 级** 左右。
**为什么它敢把流水线做这么浅？**
还记得我们前面提到的铁律吗？“流水线越深，主频飙得越高，但分支预测失败的惩罚越惨。”
苹果的设计哲学是：**我不盲目死磕高主频，我死磕“单周期执行的指令数（IPC）”。** Intel 的 i9 可以把主频飙到 5.8GHz 甚至 6.0GHz，而苹果的 M 系列大核通常死死克制在 3.5GHz ~ 4.5GHz 之间。流水线做浅，可以极大地省电，并且让分支预测失败的代价降到最低。
## **2. 它们真正的恐怖之处：丧心病狂的“超宽发射”**
既然主频没有 i9 高，为什么 M 系列能跑得一样快、甚至单核性能更强？答案就在于**宽度**。
你在 CS61C 搓的 CPU 是一次只能处理 1 条指令（Single-issue，单发射）。树莓派 5 是 4 发射，Intel i9 是 6 发射。
而苹果大核的设计直接把工业界吓傻了：
* **M2 的大核（Avalanche 架构）**：支持 **8 发射（8-wide Decode）**。这意味着在它的译码阶段（Decode），硬件一脚油门可以在一个周期内同时翻译 8 条指令！
* **M4 / M5 的大核**：苹果甚至把这个宽度进一步拓宽（达到了惊人的 **9发射 或 10发射** 级别的超宽译码流）。
💡 **超大蓄水池（ROB）：**
为了喂饱这 8~10 个发射车道，苹果做了一个极其巨大的乱序执行“蓄水池”（重排序缓冲区 Reorder Buffer, ROB）。M2 的 ROB 容量超过了 **600+** 条指令，到了 M4/M5 这一代更深。这意味着 CPU 可以同时在数千条指令里“挑”出没有依赖关系的指令并行执行。
## **3. 从 M2 到 M5，苹果在流水线和微架构上升级了啥？**
虽然它们的基本流水线深度变化不大，但内部的运算部件（ALU）和流水线旁路（Forwarding）发生了质变：
**🛠 M2 时代**
完美的 **8发射乱序架构**。它有 6 个整数 ALU，2 个分支处理单元。它的优势在于将桌面级的大流水线完美融入到了极低的功耗里，让 MacBook Air 不需要风扇也能跑满。
**🚀 M4 / M5 时代（3nm 工艺新巅峰）**
到了近期的架构，苹果主要干了三件事来压榨这条 15 级左右的流水线：
1. **更宽的执行流水线（Wider Execution Engine）**：增加了更多的下一代浮点/向量运算单元（Next-gen ML Execution Units），专门用来硬件加速大模型（LLM）矩阵运算。
3. **下一代分支预测器（Improved Branch Predictor）**：因为发射宽度变成了 9~10 发射，一旦预测失败，浪费的吞吐量太大了。苹果极大地升级了分支预测器的算法和历史表容量，确保流水线几乎“不跑空”。
5. **更深的能效核（E-Core）流水线**：苹果把小核（Efficiency Core）的执行单元也加深了，让它能在极其省电的情况下，把原本需要大核干的活也给吞掉。
## **📊 总结：四大阵营连线对比**
现在把苹果加进来，你的工业界 CPU 流水线全景图就彻底完整了：
| CPU 芯片                         | 流水线深度                          | 执行模式                           | 宽度/发射                          | 核心哲学                           |
|--------------------------------|--------------------------------|--------------------------------|--------------------------------|--------------------------------|
| STM32 (Cortex-M4)              | 3 级                            | 顺序执行 (In-Order)                | 单发射 (1-wide)                   | 绝对的死板、实时、省电。                   |
| 树莓派 5 (Cortex-A76)             | 13 级                           | 乱序执行 (OoO)                     | 4 发射 (4-wide)                  | 标准且高效率的移动/嵌入式能效平衡。             |
| Intel i9 13代 (P-Core)          | 14~19 级                        | 乱序执行 (OoO)                     | 6 发射 (6-wide)                  | 死磕高主频（5GHz+），哪怕流水线长、功耗大也在所不惜。  |
| 苹果 M2 / M4 / M5                | 14~16 级                        | 乱序执行 (OoO)                     | 8~10 发射 (Ultra-wide)           | 死磕高宽度/高IPC，用超宽的硬件并行度在低主频下干翻对手。 |



这三个芯片正好代表了工业界目前最典型的**三大金字塔层级**：从极度复杂的工业性能怪兽，到追求能效比的微型电脑，再到死磕实时性与低功耗的嵌入式单片机。
# **1. 顶级工业怪兽：Intel Core i9 13代 (Raptor Lake)**
i9-13900K 这种处理器的架构不是用简单的“多少级”就能概括的，因为它采用了**异构混合架构（x86 Hybrid Architecture）**。它内部同时塞了两种完全不同的核心，它们的流水线深度不一样：
* **P-Core (性能核/大核，Raptor Cove 架构)**：流水线深度大约在 **14 ~ 19级**。
* **E-Core (能效核/小核，Gracemont 架构)**：流水线深度大约在 **15级** 左右。
## **为什么不能简单叫它“14级流水线”？**
因为现代 i9 内部是乱序执行（Out-of-Order）和超标量（Superscalar）的。
* **前级（Front-End，取指和译码）**：是硬性的流水线，负责把输入的 x86 复杂指令翻译成 CPU 硬件自己懂的 **$\mu$ops（微操作）**。
* **中级（Execution Engine）**：是一个巨大的“蓄水池”（通常有 512 个重排序缓冲区 entries）。在这里，微操作**打破原有顺序**，只要数据准备好了就立刻送去执行。
* **后级（回退/Retirement）**：执行完后再按代码原本的顺序写回寄存器。
💡 **总结**：i9 13代是一个 **14-19级深、乱序执行、6-8发射的超标量怪兽**。
# **2. 移动能效王者：树莓派 5 (Broadcom BCM2712)**
树莓派 5 搭载的是四核 **ARM Cortex-A76** 处理器，运行在 2.4GHz。这是一个非常经典的“减重版高性能架构”。
* **流水线深度**：**13级**（指令从取指到被发射执行的基本深度）。
* **运行模式**：**乱序执行（Out-of-Order）+ 4发射超标量**。
## **它的设计精髓：**
Cortex-A76 的设计师（Arm 奥斯汀团队）在工业界非常出名，因为它们死死地把流水线卡在 **13级** 这个甜蜜点（Sweet Spot）。
* 比起桌面级 i9 的近 20 级流水线，它的分支预测失败惩罚要小得多。
* 比起手机小核（如 Cortex-A55 的 8 级顺序流水线），它的 13 级乱序流水线能榨出极高的 IPC（每周期执行指令数），非常适合树莓派这种需要跑完整 Linux 桌面系统的设备。
# **3. 实时控制利器：STM32 系列单片机**
你在做无人机（飞控、串口、传感器）或嵌入式开发时常用的 STM32，属于 **ARM Cortex-M** 阵营。它的流水线短得不可思议，**全系列都是“顺序执行（In-Order）”**。
根据你用的是具体哪一款 STM32，流水线分三档：
| STM32 内核级别                                       | 经典型号举例                                           | 流水线深度                                            | 特点                                               |
|--------------------------------------------------|--------------------------------------------------|--------------------------------------------------|--------------------------------------------------|
| Cortex-M0+ / M3                                  | STM32F103 (老战神)                                  | 2 ~ 3 级                                          | 取指 $\rightarrow$ 译码 $\rightarrow$ 执行。极其省电，门电路极少。 |
| Cortex-M4                                        | STM32F407 / F411                                 | 3 级                                              | 经典的 3 级流水线（带有分支预测分支重定向优化）。                       |
| Cortex-M7                                        | STM32H7 系列 (高性能双发)                               | 6 级                                              | 增加到 6 级，并且支持双发射（Dual-issue），可以让单片机飙到 400MHz+。    |


     **为什么 STM32 的流水线这么浅（只要 3 级）？**

 1. **确定性与实时性（Deterministic）**：单片机是用来控制硬件的（比如给无人机电调发 PWM 信号）。流水线太深或者一旦搞乱序执行，遇到中断（Interrupt）时，单片机响应会变慢。3 级流水线能保证发生中断时，CPU 可以在几个时钟周期内立刻切过去执行中断服务函数（ISR）。
3. **没有缓存（Cache）缺失的烦恼**：绝大多数 STM32 运行代码是直接从片上 Flash 读出来的，没有长达数百周期的 Memory Hazard，所以不需要深流水线来掩盖内存延迟。
## **🧐 连线思考**
* 你在 **CS61C** 搓的单周期转 **5级流水线（IF-ID-EX-MEM-WB）**，在复杂度上刚好处于 **STM32（3级）** 和 **树莓派5（13级乱序）** 之间。
* 工业界在设计 RISC-V 芯片时也是这个套路：做低功耗物联网芯片（如单片机代工）就用 2-3 级流水线；做挑战 Intel/ARM 的高性能计算（如香山处理器）就得上 10 级以上的乱序超标量流水线。

**不是，绝对不是！** “5级流水线”只是计算机体系结构中最经典的**教学模型**。在真实的工业界中，CPU的流水线级数千差万别，从只有2级、3级，到深达几十级都有。
你可以把流水线理解为一条**工厂流水线**：
* 如果一个任务很简单（比如做一个组装玩具），你可能只需要3个人分工。
* 如果任务极其复杂且追求极高产量（比如造汽车），你可能会把工序拆得极细，安排30个工人，每个人只拧一颗螺丝。
在实际的 CPU 设计中，流水线的层级是根据**应用场景**、**功耗限制**和**主频需求**来决定的：
## **1. 为什么工业界不都用 5 级流水线？**
关键在于平衡 **主频（Frequency）** 和 **延迟（Latency）/ 功耗**。
💡 **核心物理规律：** 每一级流水线所花的时间，取决于这一级里**最慢的那个组合逻辑电路（关键路径）**。
* **如果流水线太浅（比如 2 或 3 级）**：
* 每一级要干的事情太多了（例如把执行、访存、写回堆在同一级）。由于电路太复杂、信号传播走得慢，你的
* **主频根本拉不高**。
* **如果流水线太深（比如 20 或 30 级）**：
* 每一级电路极简单，主频可以飙得极高（比如 5.0 GHz+）。但是！一旦发生分支预测失败（Branch Misprediction）
* **或者**数据冲突（Data Hazard）导致流水线必须清空（Flush）时，你得付出惨痛的代价——后面几十级正在排队的指令全得扔掉，重新去取指。这被称为“流水线惩罚”。
## **2. 真实世界里的 CPU 流水线长啥样？**
我们可以看看不同时代的硬核架构在工业界是怎么选择的：
**🟢 极简/超低功耗流派（2 ~ 3 级）**
* **微控制器（MCU/单片机）**：比如物联网芯片常用的 ARM Cortex-M0+，只有 **2级流水线**（Fetch / Execute）。因为它的主频只需要几十兆赫兹（MHz），省电和省芯片面积才是第一位的，搞5级流水线反而会因为增加寄存器而费电。
* **早期的经典芯片**：比如大名鼎鼎的 **ARM7** 采用的是 **3级流水线**（Fetch / Decode / Execute）。
**🟡 经典/平衡流派（5 ~ 8 级）**
* **教科书经典**：也就是你现在学的 MIPS / RISC-V **5级流水线**（IF-ID-EX-MEM-WB）。
* **高性能嵌入式/手机大核早期**：比如 ARM Cortex-A5 采用 8 级流水线。
**🔴 现代桌面/服务器级狂魔（10 ~ 20+ 级）**
现代能跑在 4GHz - 5GHz+ 的怪兽级 CPU，流水线都深得吓人。为了提高吞吐量，它们把取指（Fetch）和译码（Decode）拆得极其细致：
* **Intel / AMD 现代处理器（如 Core i9 / Ryzen 9）**：通常拥有 **14 到 19 级流水线**。甚至在历史上，Intel 著名的奔腾4（Pentium 4 Prescott 架构）曾疯狂地将流水线推进到 **31 级**！结果因为分支预测失败代价太惨重、发热量巨大，被戏称为“高频低能”的火炉。
* **高性能 RISC-V 厂商（如香山、SiFive Performance 系列）**：它们的流水线通常也在 **10 ~ 15 级** 左右。
## **3. 5 级流水线在现代 CPU 里的新演变**
现代高性能 CPU 不仅流水线深，而且大多是 **“超标配”** 的：
1. **超标量（Superscalar）**：5级流水线一次只能流一条指令。现代 CPU 每个周期可以同时吞吐 4 到 6 条指令，相当于“多车道高速公路”。
3. **乱序执行（Out-of-Order, OoO）**：如果一条指令因为等内存被卡住了，后面没依赖关系的指令可以**越过它先执行**，最后再按顺序写回。

不同的数据类型

你的直觉非常敏锐！你总结的这四大类，直接抓住了 RISC-V 指令集（ISA）最核心的设计精髓——**按格式分流（Format-based Classification）**。
在 CS61C 的 Project 3 里，你正在做的控制单元（Control Unit）和数据通路（Datapath），其本质就是**根据指令的类型，把数据分流到不同的硬件通路上去**。
为了让你的知识体系完全闭环，我顺着你的思路，帮你把 RISC-V 完整的 **6 大指令类型** 补齐，并用最直观的“一句话大白话”帮你建立硬件肌肉记忆：
**1. R-Type (Register) —— “纯寄存器内卷”**
* **代表指令**：add, sub, and, or, sll
* **特点**：所有的源数据、目的地都在寄存器堆（Register File）里，**绝对不碰内存，也没有立即数（Immediate）**。
* **控制单元特征**：ALUSel 负责看 funct3 和 funct7 决定算加法还是减法；WBSel 毫无疑问选择把 ALU 的计算结果写回寄存器。
**2. B-Type (Branch) —— “条件大转弯”**
* **代表指令**：beq, bne, blt, bge, bltu, bgeu
* **特点**：就是你刚才推导的这类。它们拿两个寄存器做**比较**，如果条件成立，就根据指令里的**立即数**计算出一个偏移量，让程序计数器（PC）跳过去。
* **控制单元特征**：PCSel 需要根据 Branch Comp（比较器）的输出和控制单元的信号联合决定是 PC+4 还是 PC+Imm。RegWEn（寄存器写使能）必须是 **0**（分支指令不写回寄存器）。
**3. J-Type (Jump) —— “无条件狂奔”**
* **代表指令**：jal（Jump and Link）
* **特点**：不需要任何比较，**只要执行到我就必须跳**（无条件跳转）。而且它带有 "Link" 功能，会把当前指令的下一条地址（PC+4）存进寄存器（通常是 ra），方便以后用 ret 掉头回来。
* **控制单元特征**：PCSel 直接强行拉高，走 PC+Imm 通路；WBSel 选择 PC+4 写回寄存器。
**4. S-Type (Store) —— “把数据塞进内存”**
* **代表指令**：sw (Store Word), sh, sb
* **特点**：把寄存器里的数据，搬运到 RAM（内存）里存起来。
* **控制单元特征**：MemRW（内存读写信号）必须切换为 **Write**。同样，它不改变任何寄存器的值，所以 RegWEn 也是 **0**。
**💡 漏掉的最后两种（它们是亲兄弟）**
为了实现完整的 CPU，你还需要处理最后两种类型，它们其实非常好记：
**5. I-Type (Immediate / Immediate-Load) —— “带立即数的计算 / 读内存”**
它其实包含了两种看起来不同、但**硬件格式完全一样**的指令：
* **算术类**：addi, slli, xori（用寄存器里的数，加上一个指令里自带的常数）。
* **Load类**：lw (Load Word), lh, lb（从内存中**读取**数据到寄存器）。
* **为什么硬件上是一类的？** 因为它们都需要把一个寄存器的值，加上一个 12 位的立即数（作为偏移量或操作数）。
**6. U-Type (Upper Immediate) —— “搞大钱/加载高位大常数”**
* **代表指令**：lui (Load Upper Immediate), auipc
* **特点**：因为前面的 I-Type 立即数只有 12 位（最大只能表示 2048），不够大。U-Type 专门用来处理 **20 位的大立即数**，直接塞到寄存器的高位去。

brun

在 UC Berkeley **CS61C**（计算机体系结构）的上下文中，brun（或者更准确地说是 b_run / B-run）是指 **Logisim 仿真电路中的一个特定功能或控制信号**。
在 CS61C 的 Project 3（通常是使用 Logisim 或者是 Venus 模拟器设计一个完整的 RISC-V CPU）中，大家经常需要和时钟（Clock）信号以及自动化测试打交道。
具体来说，它通常代表以下两个含义之一：
**1. Logisim 中的 "Burn" / "Run"（自动时钟步进）**
在 Logisim-Evolution 仿真软件中，有一个核心功能叫做 **"Tick Half-Cycle"** 或 **"Ticks Enabled"（快捷键** Ctrl + K **或** Cmd + K**）**。
* **作用**：让时钟信号自动连续翻转（0 -> 1 -> 0），从而让你的整个 CPU 自动运行起来，而不需要你手动去一下一下点时钟。
* **绰号**：在很多 CS61C 的讨论区（Ed/Piazza）和助教（TA）的口中，连续运行电路（Auto-Ticking）经常被叫做 **"Run"** 或者电路连续高频刷新被戏称为 **"Burn"**（因为会让 CPU 满载跑仿真），合起来或者简写时常出现 brun 这种口语化表达。
**2. 自动化测试脚本中的运行命令**
在 Project 3 的本地评测（Local Testing）中，实验框架通常会提供一个 Makefile 或者 Python 脚本来比对你的 CPU 输出（*.out）与标准答案（*.ref）。
* 在编写 Bash 脚本或 Makefile 时，为了批量运行所有的 B 型（Branch，分支指令）测试用例（如 beq, bne, blt, bge），同学们或者框架经常会写一个 target 或者别名叫做 brun（即 **Branch Run** 的缩写）。
