## AgentOps 场景下的三个用途

**Token 计数器与限流**：每个 Agent 请求会触发多次 LLM 调用，成本和 QPS 都要在用户或租户维度上实时管控。单机内存计数在多实例部署下会漏算，所以要把计数状态放在 Redis，用 `INCRBY` 的原子性保证并发安全。要实现滑动窗口限流，单条命令不够用，得写 Lua 脚本，把"读旧值、判断、写新值"这套逻辑整体交给 Redis 单线程执行——常见的坑是想当然去用分布式锁，其实完全不需要。

**Agent 的短期状态**：ReAct 循环里的中间状态需要在多个 Worker 之间可见，尤其是 Agent Runtime 做无状态水平扩展时。这部分数据生命周期短、访问频繁，适合放 Redis，设置 TTL 自动过期，而不是每次都写主存储。

**幂等性**：回调可能因为网络重试而多次触发，用 Redis `SETNX` 做一次性标记，防止外部副作用被执行两次（比如真实下单）。

这三个用途能成立，本质都靠 Redis 的单线程模型——命令执行期间不会有别的命令插进来，天然保证了原子性。

## Redis 是单线程模型

Redis 由意大利程序员 Salvatore Sanfilippo（网名 antirez）在 2009 年写出来，最初是给自己做的一个网站做实时统计用的，随手写的内存数据结构服务器，发现比当时的方案好用太多就单独开源了。它的核心设定从一开始就很明确：不是要替代 MySQL，而是做一个"内存优先"的数据结构服务器——不仅存 key-value，还原生支持 List、Hash、Set、Sorted Set，这一点在当年（对比只能存字符串的 Memcached）是革命性的。

技术上真正的特点是单线程模型（6.0 之后网络 I/O 部分引入了多线程，但核心命令执行仍是单线程），靠基于 epoll 的事件循环。单线程听起来反直觉，但避免了锁竞争和上下文切换开销，配合内存操作的高速，反而做到了极高吞吐——这也是为什么"Lua 脚本能保证原子性"：脚本执行期间不会有别的命令插进来。持久化上给了两条路：RDB 做时间点快照，AOF 做操作日志追加，两者可混用平衡恢复速度和数据完整性。

## 一部开源政治剧

Sanfilippo 本人在 2020 年宣布退出 Redis 核心开发，把项目交给 Redis Labs（后改名 Redis Inc.）。之后的故事相当曲折：2024 年 3 月，Redis Inc. 把许可证从宽松的 BSD 改成 SSPL/RSAL 双授权，不再符合 OSI 对"开源"的定义，理由是云厂商（尤其 AWS）白嫖 Redis 做托管服务却不回馈社区。这个决定引发社区强烈反弹，直接催生了 **Valkey**——由 Linux Foundation/CNCF 牵头，AWS、Google Cloud、Oracle 等联合 fork 出来的社区版本，几乎所有云厂商的"Redis 兼容"托管服务后来都转向了 Valkey。

更戏剧性的是，Sanfilippo 本人在 2025 年重新回到 Redis Inc.，随后 2025 年 5 月 Redis 官方又把 Redis 8 的许可证改回了 OSI 认证的 AGPLv3，等于承认 SSPL 那步棋走错了。现在 Redis 8 是 RSALv2 / SSPLv1 / AGPLv3 三选一授权，AGPLv3 那个分支才算真正意义上重回开源。
