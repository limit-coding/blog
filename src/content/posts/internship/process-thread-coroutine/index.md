## 三个基本概念

**进程**（process）是操作系统资源分配的基本单位，拥有独立的内存空间、文件描述符等资源。进程之间相互隔离，通信要走 IPC（管道、共享内存、socket 等），开销相对较大。

**线程**（thread）是 CPU 调度的基本单位，或者说是 OS 调度器分配 CPU 时间片的最小单位，运行在进程内部，与同进程的其他线程共享内存空间和资源，但各自有独立的栈和寄存器状态。线程间通信简单，直接读写共享变量，但也因此需要锁等机制处理同步问题，开销比进程小得多。

**协程**的核心是把调度从内核态挪到用户态，运行在线程之上，由用户态调度器切换执行单元。本质是协作式多任务——协程不会被抢占，而是在遇到 IO 等待时主动让出控制权。好处是切换时不用换内核态，没有寄存器全量保存或系统调用开销，栈可以做到几 KB 可伸缩，单机能撑几十万并发单元。

多进程（multiprocessing）指多个进程并行执行任务，常见于需要绕过语言层面并发限制（比如 Python 的 GIL）或需要故障隔离的场景——一个进程崩溃不会拖垮其他进程，代价是进程间通信和状态同步更复杂。

## 三门语言的模型完全不同

这也是字节这类面试爱追问的点：

* **Python（asyncio）**：单线程事件循环，`async`/`await` 是协程语法糖，本质是生成器 + 事件循环调度。因为有 GIL，多线程本来就没法并行跑 CPU 密集型代码，线程只在 I/O 阻塞时释放 GIL 才有意义；asyncio 协程干脆连线程切换开销都省了，特别适合"发起 LLM API 请求→等响应"这种 I/O bound 场景。但一旦协程里塞了同步阻塞调用（比如没用异步版本的 `requests`），整个事件循环会卡死。
* **Go（goroutine）**：不是传统意义上的"协程"，而是 **M:N 调度**——[GMP 模型](/internship/go-gmp-scheduling)把 M 个 goroutine 复用到 N 个 OS 线程上（N 默认等于 `GOMAXPROCS`），有独立的运行时调度器做抢占式调度（Go 1.14+ 支持基于信号的异步抢占）。因为没有 GIL，goroutine 可以真并行跑在多核上，初始栈只有 2KB、按需增长，创建成本极低，所以 Go 后端很适合"一个 Agent 会话一个 goroutine"这种模型。
* **Node.js**：没有语言级协程，靠单线程 + libuv 事件循环 + Promise/async-await 实现异步。CPU 密集型代码会阻塞整个事件循环（因为只有一个主线程在跑 JS），I/O 靠 libuv 的线程池或 OS 异步 API 卸载出去，不是真正的"协程调度"。

三者的共同点是都在用某种方式规避"一个阻塞拖死一切"的问题，区别在于调度发生在哪一层：asyncio 和 Node 都停留在单线程事件循环层面（只是 I/O 模型不同），而 Go 的 GMP 是把调度器整个搬进了运行时，真正做到了多核并行。
