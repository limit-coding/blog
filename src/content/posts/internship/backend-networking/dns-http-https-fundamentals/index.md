## 完整链路

DNS 解析就是把域名翻译成 IP 地址的过程——网络层 TCP/IP 只认 IP，不认域名，浏览器请求 `example.com` 之前必须先知道它对应的服务器 IP。

具体流程：

1. 先查浏览器缓存和系统缓存（含 hosts 文件）。
2. 没有就问本地配置的 DNS 服务器（通常是运营商或路由器给的）。
3. 递归查询：依次问根域名服务器、顶级域名服务器、权威域名服务器，逐步拿到最终 IP。
4. 结果返回并缓存。

完整链路顺序是：**DNS 解析 → TCP 三次握手 → （HTTPS 多一步 TLS 握手）→ HTTP 请求响应 → TCP 四次挥手**。HTTPS 就是 HTTP 加一层 TLS：握手时服务端要出示一张与域名绑定、由 CA 签发的证书，证明这个域名确实归自己管；HTTP 握手完直接明文传输。

浏览器把所有 HTTP 页面标为 "Not Secure"（Chrome 从 2018 年起）是浏览器主动标出来的，不是网站出 bug——HTTP 明文传输，中间人可以监听篡改，且服务端身份无法验证。很多免费的推广平台、内网穿透工具愿意挂 HTTP 但不开放 HTTPS 自定义域名，是因为 HTTPS 意味着平台要帮你签发托管证书，涉及域名所有权验证、证书续期、SNI 多证书路由等运维成本；轻量服务图省事，只对付费认证用户开放。

## DNS 是一张全球分布式树状数据库

腾讯云和 Cloudflare 只是这张树上的叶子管理员。域名注册商那边有一条 NS 记录，指向谁是这个域名的权威 DNS 服务器——挂腾讯云解析就是把 NS 指向腾讯云的名字服务器，挂 Cloudflare 就是指向 Cloudflare。全球任何一台递归解析器查询时，顺着根服务器、顶级域名服务器一路问到配置的那个 NS，不管它物理部署在哪里都能查到。

Cloudflare 的优势是 Anycast 网络覆盖全球 300 多个城市，解析延迟低，带免费 HTTPS、DDoS 防护、CDN 代理；腾讯云的优势是国内合规与速度，ICP 备案网站的国内解析链路更顺畅。

## Anycast 不是 GEO DNS

一个容易搞混的点：DNS 服务商如果只有一个机房，全球查询都要绕远路。Cloudflare 用的是 **Anycast**——给域名配一个 Anycast IP，这个 IP 会被全球几百个节点同时通过 BGP 广播出去。不管在东京、北京还是纽约查这个域名，DNS 返回的都是**同一个 IP**；DNS 服务器本身不做"看你 IP 所在国家返回不同地址"的事，那是传统 GEO DNS 的做法，Cloudflare 不这样做。

真正决定连到哪个节点的，是每一条路由器根据 BGP 路由表算出的最短路径（AS Path 最短、成本最低，不是物理距离最短），这个过程发生在 IP 包路由层，跟 DNS 查询本身无关——哪怕用境外 DNS 查这个域名，拿到的也只是同一个 IP，但实际连接仍会被路由导向邻近节点。

推论：如果服务器部署在东京、域名挂在 Cloudflare，用户实际上根本"看不见"东京——TLS 握手、HTTP 请求都发生在离用户最近的边缘节点，只有缓存未命中需要回源时，才会由边缘节点发起第二段连接找回源站。

## 思想实验一：如果美国封锁国内 DNS 解析器

假设美国封杀阿里云/腾讯云的 DNS 解析器和部署在美国的服务器节点，拆成两件事看：

**封权威 NS**：如果只封阿里云/腾讯云的权威 DNS（NS），只影响权威 DNS 托管在这两家的域名。如果境外运营商拒绝路由到这些解析器，或强制 8.8.8.8/1.1.1.1 这类境内递归解析器拒绝转发查询，链路会在"递归解析器→NS"这一环断掉，域名在美国境内就查不到了。但这种封锁容易绕过——换一个未被拉黑、不在美国境内的解析器（日本、新加坡的公共 DNS，或走 DoH/DoT 加密隧道）就能继续查到，除非直接在 BGP 层面把权威 NS 的 IP 从骨干网摘除。

**封服务器 IP**：这跟 DNS 解析无关，是 IP 可达性问题——域名解析成功、拿到正确 IP，但这个 IP 被美国骨干网整体拒绝路由（类似制裁式 BGP 黑洞）。这种封锁是全球性的：任何国家的用户走到这段路由都会受影响，哪怕域名挂在 Cloudflare 上，只要原站 IP 落在被封的机房，照样连不上。

## 思想实验二：朝鲜的网络接入

互联网靠的是物理光缆或卫星线路加 BGP 路由，不是地图上的邻国关系。朝鲜全国的国际互联网出口只有两条：

1. 经中国联通，从平壤拉光纤接入全球骨干网；
2. 2017 年后经俄罗斯 TransTelecom，从图们江边拉到符拉迪沃斯托克。

理论上只要有一条线接入全球 BGP 路由体系，就能被路由到；但实际能访问和理论能路由是两回事。朝鲜全国分配的公网 IPv4 只有 1024 个，全部归属自治系统 AS131279（Star JV 公司），普通民众用的是封闭的国内光明网，压根不连全球 DNS 和公网——能触达真正互联网的只有极少数官方账号。另外许多云厂商和 CDN（如 AWS）受美国对朝制裁影响，会直接对朝鲜 IP 做地理封锁。

朝鲜有自己的国家顶级域名 `.kp`，但历史上暴露的权威 DNS 记录显示大概只有 20 个域名。问题有三层：物理链路单点脆弱（只靠两条国际出口线）、IP 资源极度紧缺（权威 DNS 服务器数量少，抗压能力弱，容易被扫崩）、国际合规链路受阻（主流域名注册商和 CA 大多是美国公司，很难跟朝鲜实体做生意，只能靠 `.kp` 或俄罗斯基础设施变通）。

一句话总结：DNS 解析和路由本身不看地理接壤，看的是谁和谁有物理电路和 BGP 层面的连接关系。
