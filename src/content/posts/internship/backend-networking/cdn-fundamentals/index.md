## 基本原理

CDN（Content Delivery Network）是一组分布在全球各地的服务器网络，把网站的静态内容（图片、CSS、JS、视频甚至 API 响应）缓存到离用户物理位置最近的节点，加速访问。

核心流程：用户请求资源时，DNS 把请求解析到延迟最低的边缘节点（Edge Node），而不是直接打到源站（Origin Server）。边缘节点有缓存就直接返回，没有则回源拉取并缓存下来。

作用：降低延迟（就近访问）；减轻源站压力（大部分请求被边缘节点挡住）；提升可用性（节点故障自动切换，也能扛 DDoS）；节约带宽成本。常见厂商：Cloudflare、Akamai、AWS CloudFront、阿里云 CDN、腾讯云 CDN。

## 缓存策略：TTL、Cache-Control、ETag

TTL（Time to Live）是缓存过期时间，由响应头 `Cache-Control: max-age=3600` 或旧式的 `Expires` 头控制，边缘节点在 TTL 内直接返回缓存，不用请求源站。

`Cache-Control` 常用值：

* `public`：可被任何缓存
* `private`：只能浏览器缓存，CDN 不能缓存，常用于带用户信息的响应
* `no-cache`：可以缓存，但每次都要向源站验证是否过期
* `no-store`：完全不缓存

**协商缓存**：原站给资源生成一个内容指纹哈希值，客户端请求时带上 `If-None-Match`（对应 ETag）和 `If-Modified-Since`。没变化就返回 304 Not Modified，变了就返回新内容和新 ETag。区别在于：ETag 校验用的是内容指纹，过期前完全不问原站；`If-Modified-Since` 是过期后才去问原站。

## 缓存失效与主动刷新

被动失效就是等 TTL 过期。但有些场景需要立即失效（比如文章紧急撤回、部署了新版本静态资源），这时需要主动刷新——CDN 厂商一般提供 API，按 URL、Tag 或前缀批量清除边缘节点缓存。

工程难点：CDN 节点分布在全球几百个 POP（Point of Presence），主动刷新要保证每个节点都收到失效指令，本质是个分布式一致性问题，通常靠消息广播而非同步等所有节点确认，所以刷新会有短暂的传播延迟，不是严格强一致。另一种更常见的工程手法是**版本化 URL**——内容一变 URL 就变，旧缓存自然不会命中，从根本上避免失效问题。

## 一致性哈希做节点路由

场景：一个边缘集群内部有多台缓存服务器，怎么决定某个 URL 该缓存在哪台机器上？如果用简单的 `hash(url) % N`，一旦增减机器（N 变化），几乎所有 URL 的映射都会变，导致缓存全部失效、瞬间大量回源。

一致性哈希把哈希值空间看成一个环（0 到 2³²-1），服务器节点和资源 key 都哈希到环上，资源顺时针找到的第一个节点就是它的归属节点。增删节点时，只有该节点在环上相邻的一小段区间的 key 会被重新分配，其余大部分映射不变。实际工程中还会引入**虚拟节点**（每台物理机在环上映射多个虚拟点），解决节点少时哈希不均匀、数据倾斜的问题。

## 回源合并防止缓存击穿

场景：某个热点资源缓存刚好过期的瞬间，如果同时有几千个请求打到同一个边缘节点，会不会全部各自发一次回源请求打向源站？如果是，源站瞬间被打爆——这就是"缓存击穿"。

解法是**请求合并/单飞**（Request Coalescing / Singleflight）：边缘节点对同一个 key 的并发回源请求做去重，只放行第一个请求真正打到源站，其余请求原地挂起等待，等第一个请求拿到结果后，一份数据分发给所有等待者。Go 里 `golang.org/x/sync/singleflight` 就是这个思路，本质是在节点内维护一个 `map[key]*sync.WaitGroup`（或 channel）做协程间的请求去重和结果广播。

字节这类面试通常会在这里往两个方向追问：一是"如果是多机房，怎么防止不同边缘节点同时回源"（单机 singleflight 管不了，需要引入分布式锁，或源站侧自己也做请求合并）；二是"如果热点 key 本身极热，单节点合并也扛不住怎么办"（这是缓存分片/多副本预热的问题了）。

## HTTPS 场景下证书如何下发到边缘节点

CDN 要给用户提供 HTTPS，边缘节点必须持有该域名的 TLS 证书私钥来完成握手。核心是证书的安全分发问题：

* **厂商托管证书**：用户上传证书和私钥到 CDN 控制台，CDN 后台同步分发到所有边缘节点（分发链路要加密，落盘要考虑私钥加密存储，避免节点被攻破后私钥泄露）。
* **Keyless SSL**（Cloudflare 提出）：私钥始终留在客户自己的服务器上，边缘节点做 TLS 握手遇到需要私钥签名的步骤时，通过专用协议把待签名数据发回客户的密钥服务器签名，再拿签名结果继续握手。边缘节点永远不持有私钥明文，代价是握手多一次网络往返。
* **ACME 协议**（Let's Encrypt 用的那套）：让 CDN 自动签发和轮转证书，域名验证走 DNS-01 或 HTTP-01 挑战，证书自动续期分发，减少人工介入。
