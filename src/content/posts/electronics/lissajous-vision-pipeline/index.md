## 为什么不用神经网络

示波器屏幕是一个背景固定、结构明确、类别很少的场景。我要识别的不是自然图像，而是直线、椭圆、圆和八字四类几何轨迹。用传统计算机视觉更快、更可解释，也更容易在树莓派上稳定运行。

最终的拍摄和识别流程是：

```text
上电后自动调焦一次并锁定
        ↓
固定分辨率、颜色通道和曝光策略
        ↓
找到屏幕四角，做透视变换
        ↓
灰度 / 颜色分离 → 二值化 → 去网格 → 形态学去噪
        ↓
提取轨迹点集和轮廓
        ↓
计算几何特征 → 四类评分 → 多帧平滑
```

## 先把相机变成确定性的传感器

视觉系统最怕参数在运行中自动漂。我的做法是把校准和正式识别分开：

1. 上电时完成一次自动调焦，之后锁住焦距；
2. 通过实验确定分辨率，不在运行时先拍超大图再压缩；
3. 固定用于提取轨迹的颜色通道，避免不同通道来回切换；
4. 帧率可以按性能调，但一轮实验中保持一致；
5. 相机和示波器位置固定后，不在每一帧重新寻找整块屏幕。

我一开始把分辨率差异误以为是焦距变化，后来才拆清楚：焦距决定清晰度，透视和采样决定几何形状。二者要分别校准。

## 透视矫正与轨迹提取

摄像头通常不会绝对正对屏幕，原本的正方形绘图区会拍成梯形。先识别绘图区四个角，再做单应性变换，把它拉回固定大小的正方形。这样后面的长宽比、主轴方向和对称性才有可比性。

轨迹提取的顺序也很关键：先用颜色或灰度阈值拉开轨迹与背景，再利用屏幕边界裁剪，最后二值化和去网格。若一上来就在整张照片上找轮廓，刻度线、文字和反光很容易比目标轨迹更显眼。

对于失谐时形成的宽带轨迹，不能只留下最细的一条边，否则会丢掉“正在快速漂移”这个重要动态信息。静态分类需要中心线，动态锁频还需要轨迹厚度和帧间变化。

## 从点集提取可解释特征

轨迹提取完成后，我主要计算以下量：

| 特征 | 说明 |
|---|---|
| `aspect` | 主轴与次轴的长度比；直线很大，圆接近 1 |
| `line_residual` | 点集拟合为直线后的残差 |
| `ellipse_residual` | 拟合单个椭圆的残差和内点比例 |
| `radius_cv` | 各点到中心距离的变异系数；圆较小，双瓣较大 |
| `center_crossing` | 中心附近的轨迹密度，用于判断八字交叉 |
| `symmetry` | 左右、上下对称程度 |
| `coverage` | 轨迹是否覆盖了完整闭环，避免把弧段当成椭圆 |

分类不是靠单个阈值，而是为四类分别打分，再比较最高分。

### 直线

直线应当细长，线性拟合残差小，不形成完整闭环，中心也不应出现八字那样的局部“打结”。主轴角度还能区分正、反斜线。

### 椭圆

椭圆是一个拉长的闭环：单椭圆拟合较好，轴比处于中间范围，中心交叉较弱，半径变化比圆大但比八字平滑。

### 圆或正椭圆

圆的长短轴接近，到中心的距离比较均匀，单椭圆拟合好，而且中心不应特别密。题目允许两轴显示比例不完全相等，所以视觉上稍扁的正椭圆也应归入这一类。

### 八字

八字不能只看外轮廓。二值图较厚时，它的外框也可能像一个圆，导致早期版本把八字判成圆。我后来把判断重点改成：

- 中心存在明显交叉；
- 到中心的距离忽大忽小；
- 单个椭圆难以覆盖两个波瓣；
- 整体仍具有较好的左右或上下对称性；
- 直线拟合不能过好。

一句话说，**外框像圆并不重要，“中心打结 + 半径不均匀”才是八字的核心。**

## 多帧平滑比抠单帧精度更重要

示波器余辉、相机噪声和自动曝光会使相邻帧略有不同。直接把每帧分类结果送给控制器，标签会在圆、椭圆和八字之间抖动。

更稳的办法是每次取 6～10 帧：

1. 单帧提取特征和类别分数；
2. 对特征做中位数或滑动平均；
3. 要求同一结果连续出现若干帧才确认；
4. 同时保留帧间差异，供锁频环判断图形是否仍在运动。

我把验收也拆成了三层：先验证屏幕框选在几十秒内不漂，再验证轨迹提取的合格帧比例，最后让信号源切换四种图形，观察平滑后的类别和频率比是否能稳定跟随。

传统 CV 的优势不只是“算得快”。它迫使我把自己看到的图形差异，写成可测量的几何量。只有误差可解释，后面的锁频、锁相和现场调试才不会变成盲猜。
