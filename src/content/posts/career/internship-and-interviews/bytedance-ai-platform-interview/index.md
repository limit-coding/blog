## 一面复盘

### 自我介绍与项目

自我介绍讲了我是谁、什么学校，然后讲了两个项目：学校课程里做的 Agent，和根据这个岗位 JD 做的 Deep Research Agent。顺着这个引出了我读 Langfuse 源码这件事——我结合项目讲了对源码的理解，同时把它和 2023 年那篇 React 论文做了对比，还提到 LangChain 不开源、Langfuse 开源，更方便吃透原理。

针对源码我讲了几点：

1. HTTP 直接发送 vs 先入队列再批量发送，我认为后者更好，能防止网络抖动，也能避免阻塞。
2. Span 用 `span.end` 结束。HTTP 错误处理：4xx 表示服务要中断，无法继续；429 或 5xx 表示服务繁忙，可以重试。
3. 重试延迟策略是指数退避：1s、2s、4s（即 1、2、4、8、16 秒递增），错开重试时间防止服务器故障时因为数据量过大被打崩。

结合自己在 Langfuse 后台的实操经验，我讲了 Start、Depose、Synthesize、Reflection 这几个阶段的流程。面试官问 Langfuse 相比 ReAct 这类 Agent 的区别，我说多了 Reflection 和打分机制——打分不理想就重新调用，把之前的建议作为新上下文继续用。我还跟同学一起测试过，加了 reflection 效果确实更好。

### Subagent、MCP 与 Skill

提到了 Subagent：学校课程作业里用 Subagent 处理文件类任务。面试官问为什么要设计 Subagent，我的解释是：如果一个 trace 里全是主 agent，上下文会非常大；把任务分给小 agent，小 agent 上下文是空的，执行完只需要返回一个结果，主 agent 不需要在自己的上下文里重复调用，避免上下文暴涨导致主 agent 表现变差。

接着聊到 MCP 和 Skill 的区别。我说 MCP 是通信协议，用了 MCP，Agent 就能直接和外部工具连接（比如 GitHub 代码库或数据库），还顺带解释了 M、C、P 三个词分别是什么。Skill 我理解成"说明书"，相当于一份 Project Instruction，用了效果比不用好。

面试官问我常用哪些 Skill，我说喜欢用官方自带的 Markdown 转 Doc、转 PPT，格式效果特别好，换其他 AI 转就没这个效果；我自己没写过 Skill，因为觉得现在民间做的 Skill 不如官方的，意义不大。他又问 Skill 和 MCP 内部具体怎么实现的，我说没看过内部实现，只能猜：Skill 里应该有明确的边界限制（"要做什么"和"不要做什么"），可能类似系统提示词，每个板块有个标识词。

### Temperature、Max Token 与 Agent 中断

讲了 temperature、top_p、max_token。Temperature 结合我之前用 Google AI Studio 的经历讲：越大越发散，越小越收敛，默认 0.7。面试官追问原理，我说不太清楚内部实现，只能按经验描述：temperature 低时模型贴着问题本身走，temperature 高时会跳出问题去生成子问题，再基于子问题继续展开。

之后问到 Agent 调用中断的问题。原因我答了网络问题和上下文超限（比如超过 200k），面试官提示了 max token——由此我才反应过来 max token 是"单次输出的最大 token 数，超出会被截断"。这让我想起 DeepSeek 刚出那阵测试时，不用 R1 这种思维链模式经常跑很久、token 超限；后来换 Gemini、Claude 之后就没再遇到过这种截断问题，具体怎么处理的我也没深究。

被问到中断后怎么恢复，我的态度是倾向于不恢复、直接开新 session；如果一定要恢复，类比 Langfuse 里 reflection/synthesize 的场景，可以停在当前状态基础上继续推进。

还聊到 tool call 和 function call 的区别，我坦白说听过但不清楚具体机制，猜测和"召回"类似——上文提到的东西如果跟当前相关，模型会自动回看一遍。

### SSE、发包顺序与 TCP 类比

聊到了大模型走 API、多个 MCP 之间怎么协同，还有给包打标记、传到服务端按标记决定接受或丢弃/重置的机制——这块我没系统学过，纯凭直觉在说。

项目里我做过 SSE 设计：不用 SSE 的话 Agent 回答会一直转圈、转完才整段输出，体验很差；用了流式输出后好很多。结果面试官以为我很懂 SSE，追着问了不少细节。我说这是昨天现学的：理解是前后端协同、基于 HTTP，把多次调用合并成一次小包传输，类似把大问题拆成小问题一点点往 HTTP 上传；但具体怎么传、ID 怎么流转，我没学过。

被问"发包时怎么保证顺序"，我说用消息队列的思路——新数据先入、旧数据后出，靠打标记来保证顺序。我还类比了 TCP 三次握手：发出去的 ACK 对不上就要么留住等对上、要么直接告诉对方重传，两种机制我也说不清哪个是真的用在这里的。

### 进程、线程、协程

用 Python 讲协程、线程、进程。我知道 Go 的 GMP，但只能讲讲自己对进程/线程/协程的理解：进程是资源分配的基本单位，线程是调度的最小单位，协程在线程之上、能反过来控制线程的执行；具体怎么用 Python 写网络层的协程调度，我没写过，答不上来。

### Claude Code 使用心得

重点讲了 Claude Code 的使用习惯。我不是直接上手 web coding，而是先在网页端和 Claude 讨论清楚要做什么，再把结论发给 Claude Code、开 Plan 模式一起做。做出初版后看效果：效果不好就补一份 CLAUDE.md；如果 Plan 模式效果不错、初版已经达标，就不需要。

第一版效果一般是常态，做完先看功能堆叠的效果：好就继续加；如果协同变差、改一个又出新 bug，就判断是架构问题，把架构精简到最小单元，跟 Claude 商量清楚哪里好哪里不好，重写 CLAUDE.md、重新设计架构后再加新功能——这样做出来的稳定性和效果都好很多。

面试官后来还问我有哪些用 Claude Code 做出来的作品。我说这种场景其实挺多：现在写的这两个网站就是用 Claude Code 做的，一般是先让它教我一遍相关的东西，再自己上手学；我还拿它调过硬件，让它写调试脚本、跑测试脚本；此外像帮忙整理博客这种杂事也常用它。

### Coding：LC84 翻车

题目是 LeetCode 84（柱状图中最大的矩形）。第一眼看着眼熟，觉得跟"接雨水"很像，跟面试官说了一嘴"应该能优化到 O(n)"。面试官问为什么，我扯了会儿双指针，发现说不通，心态有点崩。

双指针不行之后转向暴力法：两层 for 循环枚举区间、维护当前最大矩形面积。结果一直有 bug——期望输出 10，我的代码一直输出 12，最后也没调出来（单调栈的正确解法赛后补了一版，见下方）。

```cpp
class Solution {
public:
    int largestRectangleArea(vector<int>& heights) {
        stack<int> st;
        int n = heights.size();
        int maxArea = 0;
        for (int i = 0; i < n; i++) {
            while (!st.empty() && heights[i] < heights[st.top()]) {
                int h = heights[st.top()];
                st.pop();
                int left = st.empty() ? -1 : st.top();
                maxArea = max(maxArea, h * (i - left - 1));
            }
            st.push(i);
        }
        while (!st.empty()) {
            int h = heights[st.top()];
            st.pop();
            int left = st.empty() ? -1 : st.top();
            maxArea = max(maxArea, h * (n - left - 1));
        }
        return maxArea;
    }
};
```

栈里维护的是下标，栈顶对应当前高度；一旦遇到比栈顶矮的柱子，就说明栈顶柱子的右边界确定了，可以结算它能撑起的最大矩形。

## 反思

**优点**：这次讲的东西都有依据——论文和源码我是真读过的，Claude 之前给我的建议也确实是对的；对 Claude Code 的使用体验很深，面试官提到的设计理念我基本都能接上；整场不怯场，更像一场技术交流。

**缺点**：coding 没写出来；计算机网络相关的很多东西答得不对，本质是没系统学过；Agent 里 temperature、调用机制、tool call、MCP 这些具体怎么实现的，我都说不清楚；hot100 还没刷完，多刷几遍效果会好很多，而且字节的 coding 是输入输出的形式，我用 ACM 打法也行，但还不够熟练。归根结底：agent 看着是应用层，往下挖全是计算机网络和系统的底子，把这块基础打扎实才是正解。

**价值**：一是对大厂祛魅——字节的技术不见得比 Claude 强；二是印证了"学最新最好的技术"这条主线是对的；三是借这次交流理清了自己对 Agent 的理解、看清了短板（操作系统和网络层），也算是给自己定了下一步要补的东西。之后想做一个 Coding Agent，加深对 Claude Code 本身的理解——目前我对它的理解还停留在用户表层。

这次面试的起因，是学校一门课程作业做的推荐系统，一开始设计的其实不是 Agent——最初想结合已有资料做课程推荐，但推荐效果差，一度把推荐功能整个砍掉，答辩时也没达到预期。后来我一点点手动把各种资料整理成结构化的 JSON 数据库，事后才知道这套做法有个名字叫 structured RAG，又陆续加上了反思和 SSE，整个系统才跑通闭环。我当时完全不知道这套东西叫"Agent"——是后来跟 Claude 聊这个项目，Claude 分析完告诉我这就是 Agent，才反应过来。一门课程作业顺手迭代了 40 多个 commit，能作为敲门砖拿到字节这场面试，也算是意外之喜。

前后端不是我的主业，我的主线是卫星通信、芯片设计、计算机网络、机身智能和 AI Infra 这五个方向。这次算是撞上的一次"支线任务"：好处是能借高手对局校准一下自己的技术水平、明确该补的基础；代价是它终究不是我规划路径里的东西，不必因为一次表现不完美就焦虑。继续把网络和操作系统的基础课补上、hot100 每天刷一两道，短板补齐之后再面，大概率是另一个结果。
